# 실측 데이터와 파라미터 근거

이 문서는 **모든 파라미터가 왜 그 값인지**를 실측 데이터로 설명합니다.
다른 환경에서 재현할 때는 같은 측정을 다시 하고 값을 조정하세요.

측정일: 2026-08-04 / 장비: Go2 EDU + 확장독 Jetson Orin Nano

---

## 측정 1 — 시계 오프셋

```
offset = -49.1263 s   (min -49.1641 / max -49.1196)
```

**해석**: LiDAR를 발행하는 메인 컨트롤 보드가 확장독보다 49초 뒤처짐.
편차 0.045초로 매우 일정 → 드리프트가 아닌 상수 오프셋.

**영향**: `pointcloud_to_laserscan`처럼 클라우드 원본 스탬프로 TF를 조회하는
방식은 tf2 버퍼(기본 10초) 밖 조회가 되어 실패하거나 오동작.

**대응**: `scan_maker`는 클라우드 원본 스탬프를 **읽지 않음**.
수신 시점의 로컬 시계로 스캔·TF를 함께 찍으므로 시계 문제가 원천 소멸.

측정: `python3 tools/clock_offset.py`

## 측정 2 — 포인트클라우드 구조

```
=== PointCloud2 구조 ===
  frame_id  : odom
  w x h     : 11554 x 1 = 11554
  point_step: 32   is_dense: True
  field x            offset= 0 type=7
  field y            offset= 4 type=7
  field z            offset= 8 type=7
  field intensity    offset=16 type=7

=== 포인트 분류 (12 프레임, 총 138668점) ===
  NaN/Inf     :       0 (0.0%)
  정확히 0,0,0:  120000 (86.5%)  <- 더미
  유효        :   18668 (13.5%)  = 프레임당 1556점
```

### 핵심 발견 A — 더미 포인트 86.5%

`is_dense: True`이고 NaN이 0개입니다. 즉 L1은 무효 반환을 NaN이 아니라
**`(0,0,0)`으로 채워서** 보냅니다.

**왜 치명적인가**: 이 점들은 odom 좌표계 원점에 고정됩니다. 로봇이 5m
이동하면 출발점 위치에 거대한 가짜 장애물 덩어리가 나타납니다.
`np.isfinite()`는 0을 통과시키므로 일반적인 필터로는 안 걸립니다.

**대응 코드** (`scan_maker.py`):
```python
ok = np.isfinite(p).all(axis=1)
ok &= ~((np.abs(p[:,0]) < 1e-6) &
        (np.abs(p[:,1]) < 1e-6) &
        (np.abs(p[:,2]) < 1e-6))
```

### 핵심 발견 B — 유효점 수가 L1 사양과 일치

프레임당 1,556점. L1 사양은 21,600 pts/s ÷ 11 Hz ≈ 1,960점.
거의 일치하므로 더미 필터가 정확히 동작한다는 교차 검증이 됩니다.

측정: `python3 tools/cloud_inspect.py`

## 측정 3 — odom 좌표계의 정체

| 자세 | `robot_odom.pose.z` |
|---|---|
| 엎드림 | +0.053 m |
| 기립 | **+0.322 m** |

기립 시 0.322는 Go2 몸통 높이와 정확히 일치합니다.

**결론**: **odom의 z=0 = 시작 지점의 바닥면**. `pose.z`는 바닥 위 몸통 높이.

**설계 반영**: `base_footprint`를 `z=0`에 고정하는 것이 물리적으로 정확.
높이 슬라이스 값이 곧 "바닥으로부터의 절대 높이"가 됩니다.

## 측정 4 — 유효점의 공간 분포

```
=== 유효점 Z 분포 (odom frame) ===
  p0    -0.429 m      p50   -0.051 m      p95   +0.651 m
  p1    -0.173 m      p75   +0.001 m      p99   +1.292 m
  p10   -0.097 m      p90   +0.364 m      p100  +2.203 m

=== 수평거리 분포 ===
  p0    0.30 m    p50   0.95 m    p95   5.02 m
  p1    0.34 m    p99   7.46 m    p100  7.83 m
```

### 해석

**바닥이 -0.12 ~ -0.05 m에 집중.** odom 원점보다 살짝 아래.

**수평거리 p50 = 0.95 m.** 유효점의 절반이 로봇 반경 1m 안쪽입니다.
L1이 Go2 머리에 **앞아래로 기울어** 장착되어 근거리 바닥을 주로 봅니다.
→ 이것이 "벽에서 1.5~2m 유지하며 주행"이 필수인 이유입니다.

**최대 거리 7.83 m.** 사양상 30m지만 실내 실측은 8m 미만.
→ `range_max: 12.0`, `max_laser_range: 10.0` (여유만 두고 과대설정 금지)

**Z p90 = 0.364 m.** 0.6m 위에는 점이 거의 없음.
→ 높이 슬라이스 상한을 0.60 이상으로 올려도 무의미

측정: `python3 tools/cloud_inspect.py`

### 빔 2.0도 (180빔) — 채택

| 밴드(m) | 4f | 6f | **8f** | 10f |
|---|---|---|---|---|
| [-0.02, 0.60] | 57 | 59 | 60 | 62 |
| [0.02, 0.60] | 51 | 53 | 55 | 56 |
| **[0.05, 0.60]** | 49 | 51 | **53** | 53 |
| [0.08, 0.60] | 48 | 49 | 51 | 51 |

### 결정: `[0.05, 0.60]` / 2.0도 / 8프레임(0.75초)

| 선택 | 근거 |
|---|---|
| **빔 2.0도** | 1.0도 대비 +3~6%p. 빈당 점이 여러 개 들어가 노이즈 감소. 실내 2D SLAM에 180빔은 충분. slam_toolbox의 correlative scan matching은 빔 개수보다 **각도 커버리지**에 민감 |
| **하한 0.05** | 실측 바닥(-0.116~-0.05)에서 **10cm 여유**. `[0.02]`가 +2%p 높지만 보행 중 몸이 기울면 바닥이 밴드에 들어와 가짜 장애물 발생. 2%p를 위해 감수할 위험이 아님 |
| **상한 0.60** | 그 위에 점이 없음(Z p90=0.364). 올려도 무의미 |
| **8프레임** | 10f도 53%로 동일 = **포화점**. 8f가 효율적이고 지연도 0.75초로 짧음 |

**53%는 실용 상한에 가깝습니다.** L1의 물리적 한계(21,600 pts/s, 86.5% 더미)를
감안하면 이 이상은 어렵습니다.

측정: `AINC=2.0 python3 tools/band_sweep.py`

## 측정 7 — 맵 품질 (최종 검증)

시험 매핑(방 하나, 13.5 x 9.8 m):

```
파일: test02.pgm (196, 271)
  점유 6.42%  자유 93.58%  미지 0.00%
  점유/자유 = 0.0686  (정상 0.02~0.06)
  벽 평균 이웃수 2.51  (2.0~2.6 얇음 / 3.0+ 이중벽 의심)
  판정: 양호
```

### 해석

**벽 평균 이웃수 2.51이 핵심 지표입니다.** 점유 픽셀의 4-이웃 중 몇 개가
점유인지의 평균. 벽이 1~2px 두께의 깔끔한 선이면 2.0~2.6.
이중벽이면 3.0 초과. **2.51 = 이중벽 없음 = 루프 폐합 성공.**

**점유/자유 0.0686이 기준을 살짝 넘은 것은 무시 가능**:
- 미지 0.00% → 맵이 스캔 영역에 딱 맞게 잘려 분모(자유)가 작음
- 방 하나 규모라 벽 대비 내부 면적이 작음
- 넓은 공간을 매핑하면 자연히 0.03~0.04로 하락

측정: `python3 tools/eval_map.py ~/maps/이름.pgm`

## 측정 8 — 주행 방식이 맵 품질을 좌우한다

동일 파이프라인·동일 파라미터로 두 번 매핑한 결과 비교.

### 실패: 방 중앙에서 원형 20m 1바퀴

- 벽이 연속된 선이 아니라 **흩뿌려진 점**
- 좌·우상단에 **부채꼴 번짐**
- 자유공간이 벽 밖으로 **누출**

**원인**: 방 중앙에서는 벽까지 5~7m. 유효점 수평거리 p50이 0.95m이므로
그 거리의 점은 전체의 5% 남짓. **벽에 닿는 점이 절대 부족.**
성긴 점 사이로 레이캐스팅이 새어나감.

### 성공: 벽에서 1.5~2m 유지, 사각형, 코너 정지, 양방향

- 벽이 **끊김 없는 한 겹 선**
- 직각 코너가 **90도 유지**
- 자유공간이 벽 안에 **갇힘**
- 내부 구조물(기둥·파티션)도 또렷
- 벽 평균 이웃수 **2.51**

**결론**: **주행 방식이 파라미터만큼 중요합니다.**
